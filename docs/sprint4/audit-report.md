## 3. План роботи АО

1. **Зберегти базову точку аудиту.** Зафіксувати URL репозиторію, гілку/commit SHA, дату, ОС, `mvn -v`, `java -version` і версію Chrome. Не змінювати тестовий код до збереження первинних логів.
2. **Чисте відтворення за README.** Клонувати в окрему порожню папку; виконати спочатку `mvn -v`, потім дві README-команди без додаткових параметрів. Зберегти повний stdout/stderr і `target/surefire-reports` після кожного запуску. Записати, чи це чистий клон і який commit перевірено.
3. **Перевірити власні UT-17–UT-20.** Зіставити кожен тест з відповідною вимогою/правилом і межами; підтвердити фактичний результат за звітом; для червоних тестів знайти відповідний issue або зафіксувати відсутність зв'язку. Не виправляти реалізацію чи тести без окремого дозволу.
4. **Перевірити UI-07/UI-08.** Зафіксувати передумови, URL, фактичні локатори, результат і точку тайм-ауту. UI-07 позначити як пройдений лише для наданого повного прогону; UI-08 — як помилку виконання тесту до встановлення першопричини.
5. **Незалежно перевірити трасованість.** Звірити покриття BL-вимог із матрицею, а тестові ID з реальними методами/анотаціями та Issue. Порожню `ui-scenarios.md` і відсутню detail-матрицю зафіксувати як прогалини командних артефактів, а не заповнювати від імені їхніх виконавців.
6. **Звірити дефекти.** Для кожного Issue перевірити вимогу, ручний TC, автоматизований тест, severity/priority, кроки, expected/actual, докази та поточний статус. Розрізняти дефект продукту, тесту й середовища.
7. **Передати розбіжності відповідальним.** Surefire summary — КТ; детальна coverage matrix та UI сценарії — ТА; Selenium IDE файли/експорт — ІТ; статуси й час у Task Board — відповідальному за дошку. АО записує незалежний висновок і посилання на докази.
8. **Підготувати демо-рецензію.** Зібрати перелік слабких місць із доказами і питання, які може поставити замовник: чому `mvn clean test` не запускає UI за конфігурації `excludedGroups=ui`; які дефекти модуля підтверджені BL і чи є для них Issues; чому Surefire summary має лише 8 тестів; як пояснити розбіжності SRS/Issue #3 та SRS/Issue #9; чи відповідають UI-01/UI-02 реальним сценаріям, коли зараз лише ініціалізують WebDriver.
