### 3.3. Уточнення та повторна перевірка власного UI-08

Діагностика сторінки `https://automationintesting.online/` виявила, що елемент з `id=submitContact` відсутній (`found: 0`), але видима кнопка з текстом `Submit` існує. Після зміни локатора на `//button[normalize-space()='Submit']` звичайний Selenium `.click()` завершився `ElementClickInterceptedException`. Після прокрутки й виконання JavaScript-кліку сценарій пройшов, включно з перевірками імені, теми та зникнення кнопки форми.

Останній окремий прогін **18.11.2026 о 19:09 (Europe/Kyiv)** після видалення діагностичних повідомлень:

```text
-Dtest=MykhailenkoUiTest -DexcludedGroups=none test
Tests run: 2, Failures: 0, Errors: 0, Skipped: 0
BUILD SUCCESS
```

**Обмеження:** JavaScript-клік обходить перевірку перекриття елемента, тому цей результат підтверджує виконання автосценарію, але не підтверджує, що кнопку можна натиснути звичайним користувацьким кліком. Після виправлення власного класу повний набір із 62 виконань повторно не запускався.

## 5. Звірка Maven Surefire з командним підсумком

У документі КТ `docs/sprint4/surefire-summary.md` (дата 16.11.2026) зазначено:

| Команда | Surefire КТ (16.11) | Незалежний прогін АО (18.11) |
|---|---|---|
| `mvn clean test` | 46 / 13 / 0 / 0 | **54 / 13 / 0 / 0** |
| `mvn test -DexcludedGroups=none` | 54 / 13 / 0 / 0 | **62 / 13 / 6 / 0** |

Формат: `Tests run / Failures / Errors / Skipped`. Обидва незалежні запуски — `BUILD FAILURE`.

У `README.md` також записано 54 виконання і 0 Errors, що не відображає незалежного повного прогону 18.11. Розбіжності могли виникнути через різні дати, версії коду чи середовище (у КТ — JDK 17/Maven 3.9.16, у АО — JDK 21/Maven 3.10.0). **Без порівняння точних SHA не можна стверджувати, що підсумок КТ був неправильним для його власного прогону.** Потрібно уточнити SHA, зберегти Surefire-логи й синхронізувати останній спільний підсумок.

## 7. Висновок АО

Для закриття всього спринту потрібна спільна звірка версій і Surefire, стабілізація решти UI-сценаріїв та повторний повний прогін на одному зафіксованому SHA. АО документує виявлене; виправлення бізнес-логіки й чужих тестів виконують відповідальні учасники. Статус завдання №28 у Task Board змінюється після прийняття результатів СМ/КТ.
