## Перелік питань для Demo

1. **Щодо нетестованих типів:** У плані тестування вказано, що інсталяційне, локализаційне та порівняльне тестування не застосовуються. Чи підтверджуєте ви, що відсутність цих перевірок не створить ризиків для кінцевої якості продукту StayNow?
2. **Щодо вартості розробки:** Ми виправили дефекти однозначності у деяких вимогах (наприклад, щодо формату email чи часу дії сесії). Чи не призведе така конкретизація до збільшення очікуваної вартості або строків розробки модуля?
3. **Щодо інструментів тестування:** У Test Plan для навантажувального тестування (типи 16-18) вказано використання JMeter або k6. Чи достатньо цих інструментів, враховуючи, що на Demo ми не зможемо повноцінно показати процес навантаження наживо через брак часу?
4. **Щодо тестових даних:** Як ви бачите процес генерації тестових даних для перевірки «умов гонок» (Race Conditions) при одночасному бронюванні одного номера, якщо в поточній demo-версії дані періодично автоматично скидаються?
5. **Щодо відхилених дефектів:** У нашому реєстрі є відхилені дефекти (наприклад, відсутність кнопки Logout на сторінці входу). Чому ви, як замовник, погоджуєтеся з такою логікою, якщо вона може вплинути на розуміння інтерфейсу користувачем?
